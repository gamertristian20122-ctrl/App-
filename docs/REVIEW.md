# Review fixes (after the end-to-end run)

Three reviewers (security, money, MCP) reported 18 findings on the e2e build. For each one I
re-read the code, checked whether it was real, and either fixed it with a regression test or
recorded why not. All 18 were real; none had been fixed by the e2e pass. 16 are fully fixed. 2 (13 and
15) are fixed without adding MCP tools. A dedicated tool needs plan approval (CLAUDE.md: plan
before coding; the v1 tool list is fixed), so those tools are proposed below.

Schema change: `supabase/migrations/0003_review_fixes.sql` adds `posts.canceled_by` and
`oauth_codes.family_id`. Both are nullable, so the migration is safe for existing rows.

Checks after the fixes: `pnpm typecheck`, `pnpm lint`, `pnpm test` (core 273, transcription 59,
storage 88, posting 175, db 177 + 11 Postgres-only skipped, services 140, mcp 55, worker 125,
web 163), `pnpm -F @app/web build` (no warnings) and `pnpm e2e` all pass.

## Security

| # | Finding | Decision |
| --- | --- | --- |
| 1 | Approval surfaces hide publishable options (first comment, collaborators, privacy, page/board/playlist ids) | **Fixed.** Core `PLATFORM_OPTION_LABELS` is typed so every key of every `PlatformOptionsSchemas` entry must have a label. A new option will not compile until it gets one. `describeOptions()` turns a variant's options into label/value lines; keys it does not know (for example from older rows) are shown by name, never hidden. `services.drafts.preview` returns `PreviewVariant.optionLines`, and the approval card (`optionsList`), `/approve/[nonce]` (`OptionList`) and the `/app/approvals` queue (`PreviewCard`) all render them. TikTok's "Who can see" is left out only where its picker already shows it. Tests: `core/test/validation.test.ts` (every schema key is labelled and described), `mcp/test/card.test.ts` (the hidden Instagram first comment and collaborators appear in the card), `web/test/ui/approvals.test.tsx` (queue and `OptionList`). |
| 2 | Cancelling a post does not revoke the approval, so the AI can publish it again | **Fixed.** `posts.cancel` records `canceled_by` (the `via`, default `'web'`). `posts.schedule` refuses (`conflict`, `reason: 'canceled_by_user'`) a variant whose post the person cancelled after the current approval (same `approved_revision`, cancelled after `approved_at`), unless the call is `via: 'web'`. A new approval (edit + approve, or reject + approve) clears it. I did not move the draft out of `approved`: `claimForPublish` checks the draft's approval, so that would also stop the draft's other, still-scheduled variants. System cancels (account disconnected, brand archived) leave `canceled_by` null and do not withdraw. Tests: `services/test/posts.test.ts` (approve → schedule → cancel(web) → schedule(mcp) fails; the other variant and the web path still work; re-approval and system cancels). |
| 3 | Open redirect through DCR: authorize errors auto-redirect to an attacker-registered URI | **Fixed** in the web layer. `loadConsent` never returns a redirect for a validation error any more. The page shows the error and, when the client and redirect URI are verified, a "Return to `<host>`" link the person has to click. Only the person's own Allow/Deny still redirects automatically. The services still put `details.redirectTo` on the error, so the web decides how to use it. Test: `web/test/api/oauth.test.ts` (bad PKCE, wrong resource and `response_type=token`, signed in or not, all give `kind: 'error'` with `returnTo`). |
| 4 | Authorization-code reuse not handled; anyone holding the code can burn it | **Fixed.** `token()` looks the code up and checks client, redirect URI, PKCE and resource first. Only then does the bound `consumeCode(..., { clientId, codeChallenge, familyId })` mark it used and record the token family it issues. A code that was already used revokes that family (OAuth 2.1 §4.1.3), including when it loses a race to a concurrent redemption. A wrong verifier or client no longer uses up the code. Tests: `services/test/oauth.test.ts` (both orders), `db/test/repos-auth.test.ts` (bound consume), `web/test/api/oauth.test.ts` (tokens from a replayed code stop working). |

## Money

| # | Finding | Decision |
| --- | --- | --- |
| 5 | Drive links skip the storage limit and the clip-time check, and refused files stay in R2 | **Fixed.** `registerDriveLink` runs under the user lock and refuses when no clip time is left, when storage is full, or when 3 links are still waiting to download (`config.maxPendingDriveLinks`). `markIngested` checks storage again with the real size. A refused ingest (`markIngested`) or a failed one (`markFailed`) deletes the stored file. `markFailed` leaves ready or deleted media alone. Tests: `services/test/media-usage.test.ts`. |
| 6 | A late `invoice.payment_failed` overwrites a recovery; a failed fetch falls back to the stale payload | **Fixed.** With a Stripe client, `invoice.payment_failed` fetches the subscription and applies it (`applySubscriptionIn`), so a late retry after the user paid leaves them active. `latestSubscription` throws when the fetch fails, so the event stays unprocessed and Stripe retries it; it is never applied from the stale payload. Without a Stripe key (local dev, tests) the old behaviour stays. Tests: `services/test/billing.test.ts`. |
| 7 | Retention deletes clip sources that a draft or scheduled post still uses | **Fixed.** `listStaleSourceMedia` skips sources attached to a draft in `draft`/`approved` or to a `scheduled`/`publishing` post. They still count toward storage, and they are deleted once the draft or post is done. Test: `services/test/accounts-jobs.test.ts` (an attached source is kept, then deleted after the draft is archived). |
| 8 | Held posts fill every due-post sweep batch, and each one adds 4 jobs a day forever | **Fixed.** `listDuePosts` returns only due posts that have no live `publish_post` job (queued, running, or failed awaiting retry). Held posts always have their next check queued, so they never fill a batch. If a post's sweep job died, or succeeded while the post stayed scheduled, the post is failed with a clear message instead of being swept forever. Held posts are checked less often over time: 6 h, then half of how long they have been held, at most once a week. `requeueHeldPostsIn` queues them to publish right away when billing becomes active again (`applySubscriptionIn`) or a paused brand is restored (`brands.restore`, `reconcileBrandLimitIn`). Tests: `services/test/posts.test.ts` and `accounts-jobs.test.ts`. |
| 9 | Trials, and paying users with a late renewal webhook, get a second clip allowance | **Fixed.** An in-app trial meters over the trial itself (`[trialEndsAt − 7 d, trialEndsAt)`, `entitlements.periodFor`). A Stripe period that has ended rolls forward with the same length (`core usagePeriod`), so it starts where Stripe's next period starts and the usage still counts when the webhook arrives. Tests: `core/test/time.test.ts` and `services/test/media-usage.test.ts`. `ARCHITECTURE.md` is updated. |
| 10 | Overlapping cleanups fail a post whose resume job the other cleanup just queued | **Fixed.** When the resume or recheck job already exists, `recoverStuckPublishing` fails the post only if that job is `dead` or `succeeded`. Test: `services/test/posts.test.ts`. |
| 11 | Clips stay `queued`/`rendering` forever when their render job dies | **Fixed.** `maintenance.listOrphanedClips` finds clips with no live `clip_render` job after 30 minutes, and cleanup fails them through `clips.failRender`. That frees their slot so they can be requested again (`CleanupResult.failedClips`). Test: `services/test/accounts-jobs.test.ts`. |
| 12 | Spring-forward gap times land an hour early in western zones | **Fixed.** `zonedLocalToUtc` checks that the result reads back as the input; for a time in the gap it uses the offset from before the change (02:30 → 03:30 EDT/PDT, never 01:30). Tests: `web/test/ui/lib.test.ts` (New York, Los Angeles, Berlin, neighbouring times, fall-back). |

## MCP

| # | Finding | Decision |
| --- | --- | --- |
| 13 | The model cannot read the voice profile, the clip rules or the week-over-week data (only in prompts) | **Fixed, without adding tools.** `list_accounts` with a `brandId`, or when there is only one brand, returns the brand's writing brief: voice profile, best imported posts and the rules for its connected platforms. It also returns the full profile JSON (`structuredContent.voiceProfile`). `save_voice_profile` says it replaces the whole profile and that the model should read it there first and send it back complete. `get_transcript` includes the pick_clips rules, and `get_analytics` with a `brandId` (7 days) adds the weekly review and the steps for proposing experiments. The server instructions and tool descriptions name tools instead of prompts; the prompts stay as user shortcuts and share the same text (`playbook.ts`). **Proposed, needs approval:** a read-only `get_writing_brief` (or `get_voice_profile`) tool and a merge mode for `save_voice_profile`. Tests: `mcp/test/tools.test.ts` ("tool paths to the playbook"). |
| 14 | `get_transcript` without a range prints and repeats every segment (about 285k characters for 2 h) | **Fixed.** Segments are cut off at a budget of 40k characters, and the response includes `nextStartMs` so the model can page. `structuredContent` holds only the segments shown, plus words only for short ranges; it never has the whole transcript. The `pick_clips` prompt pages the same way. Tests: `mcp/test/tools.test.ts` and `prompts.test.ts` (2 h, 1,200 segments: under 45k characters of text and under 80k of JSON). |
| 15 | No way to find image, audio or non-source video ids | **Fixed, without adding tools.** `get_transcript` with no arguments lists the media library: source videos, plus ready images, audio and other videos with ids, each labelled with the tools that take it. The server instructions and the render tool descriptions point there. The `/app/media` page shows each id, ready to copy. **Proposed, needs approval:** a dedicated read-only `list_media { kind }` tool. Tests: `mcp/test/tools.test.ts`, `web/test/ui/views.test.tsx`. |
| 16 | Word timings only in `structuredContent`, which the model may not see | **Fixed.** Ranged requests of 5 minutes or less print the timings in the text as `word@startMs` (up to 12k characters, with a note when cut). For longer ranges the text says how to get them. Test: `mcp/test/tools.test.ts`. |
| 17 | Prompt arguments need raw UUIDs, and there is no completion | **Fixed.** `brand_id` and `media_id` are completable (brand names; recent source ids), and the server advertises the `completions` capability. `brand_id` accepts a brand name and is optional when there is one active brand. `media_id` defaults to the newest source video. SDK 1.32 looks for the completer on the inner schema when it registers a prompt but on the outer schema when it answers, so `optionalCompletable` sets it on both. Tests: `mcp/test/prompts.test.ts`. |
| 18 | The suspended-brand error is an upgrade prompt inside the AI app | **Fixed on the MCP path.** `modelMessage()` (tool errors and prompt errors) rewrites every `payment_required` error in neutral words, using `details.reason` (`brand_suspended`, `trial_ended`) and `details.status`. The next step reads "The user can manage their account and brands in the web app." The web app keeps its own wording. Test: `mcp/test/tools.test.ts`. |
